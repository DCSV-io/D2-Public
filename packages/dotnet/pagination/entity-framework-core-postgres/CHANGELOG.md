## 0.3.0 - 2026-08-04
### Added

- `SearchBlobModelBuilderExtensions.WHITESPACE_CLASS`: the character class the
  stored column's whitespace collapse is defined over, written out as
  codepoints so it admits exactly what `char.IsWhiteSpace` admits on the query
  side.
### Changed

- Dependency update: DcsvIo.D2.Pagination bumped.
- Dependency update: DcsvIo.D2.Pagination.EntityFrameworkCore bumped.
- The remarks on `TrigramSearchDialect<TRow>` state that
  `SearchQuery.Normalized` arrives case-folded, and that the fold is what binds
  a cursor to its query rather than what makes the match case-insensitive. The
  previous text said `Normalized` arrives unfolded, which the query side does
  not do.
### Fixed

- The stored column collapses whitespace over an explicit character class
  rather than the provider's `\s` shorthand. `\s` resolves to `[[:space:]]`
  under the database's ctype, which in the glibc UTF-8 locales excludes U+00A0
  and U+202F while `char.IsWhiteSpace` admits both, so a row whose source text
  contained one of those kept it verbatim in the blob while the caller's
  identical text had it collapsed - and the row could not be found by its own
  text. `HasD2SearchBlob` therefore emits a different column expression than
  0.2.0 did, and a model already created against 0.2.0 needs a migration to
  adopt it.
## 0.2.0 - 2026-08-04
### API-breaking

- `TrigramSearchDialect<TRow>.EscapeCharacter` is renamed `ESCAPE_CHARACTER`,
  and `SearchBlobModelBuilderExtensions.IndexMethod` and `IndexOperatorClass`
  are renamed `INDEX_METHOD` and `INDEX_OPERATOR_CLASS`, following the
  constant-naming convention.
### Changed

- Dependency update: DcsvIo.D2.Pagination bumped.
- Dependency update: DcsvIo.D2.Pagination.EntityFrameworkCore bumped.
### Fixed

- The generated blob column is built from immutable operators only. PostgreSQL
  rejects a stored generated column whose expression is not immutable, and
  `concat_ws` - the obvious way to write the join - is marked stable, so
  declaring the column failed at schema creation with `42P17` and no model
  containing it could be created at all. The join is a coalesced concatenation
  now, and the whitespace collapse runs before the trim so a source beginning
  with a tab leaves no leading space behind.
- The caller's search text is bound as a query parameter rather than placed in
  the expression tree as a constant. Entity Framework renders a constant inline
  in the command text, which put the caller's search text - a person's name or
  electronic mail address on the surfaces this exists for - into the provider's
  command logger and its exception detail with no sensitive-data logging switch
  involved, and gave every distinct term its own statement, its own plan and its
  own compiled-query cache entry.
## 0.1.0

### Added

- Initial PostgreSQL leaf of the list-search capability.
- `TrigramSearchDialect<TRow>`: a case-insensitive containment pattern for the
  filter and weighted trigram similarity for the score, in that order, so the
  index-accelerated stage narrows to candidates before ranking runs.
- `TrigramSearchDialect<TRow>.EscapePattern` and `EscapeCharacter`: the pattern
  metacharacters and the escape character are escaped and an explicit escape
  clause is emitted, so a query of wildcards matches the rows containing those
  characters rather than every row.
- `HasD2SearchBlob` on `EntityTypeBuilder<TEntity>`: declares the generated blob
  column, its index and its sources. The column joins its sources with a single
  space in declared order, contributes nothing for an absent source without
  doubling separators, collapses whitespace runs to one space, and is not
  case-folded.
- `SearchBlobModelBuilderExtensions.IndexMethod` and `IndexOperatorClass`.
- `ToTrigramSearchPageAsync` on `IQueryable<TRow>`: one trigram-backed search
  page, supplying the dialect the provider-neutral overload requires.
