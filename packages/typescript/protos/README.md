# @dcsv-io/d2-protos

Buf-generated TS modules + gRPC client stubs from `contracts/protos/`.
Mirrors `DcsvIo.D2.Result.Grpc` (.NET, generated by `Grpc.Tools` at csproj
build time), which compiles `d2_result.proto`.

## Install

```bash
pnpm add @dcsv-io/d2-protos
```

## Public API

The generation workflow (Buf + ts-proto) runs via `pnpm generate` and writes
output that is committed to git, so consumers do not need to run codegen on
first build. Each `contracts/protos/d2/common/v2/*.proto` file (package
`d2.common.v2`) generates into `src/generated/d2/common/v2/{name}.ts` through
the `generate` script. `src/index.ts` re-exports only part of the generated
output, listed below; the other files under `src/generated/` are not re-exported.

Re-exports from `src/index.ts`:

| Export            | Source file                           | Purpose                                                                    |
| ----------------- | ------------------------------------- | -------------------------------------------------------------------------- |
| `D2ResultProto`   | `generated/d2/common/v2/d2_result.ts` | Full `D2Result` wire envelope (success, status, errorCode, category, ...). |
| `TKMessageProto`  | `generated/d2/common/v2/d2_result.ts` | Translation-key message with `map<string,string> params`.                  |
| `InputErrorProto` | `generated/d2/common/v2/d2_result.ts` | Field-level validation error: field name + `TKMessageProto[]` errors.      |

The codec (`d2ResultToProto` / `d2ResultFromProto` / `handleGrpcCall`) that
converts between `D2Result` and `D2ResultProto` is host-supplied
and is not part of this package, which is the generated-stub layer only.

## Dependencies

- `@bufbuild/protobuf` - runtime types for proto-generated code.
- `@grpc/grpc-js` - gRPC client transport.
- `@bufbuild/buf` (devDep) - codegen tooling.
- `ts-proto` (devDep) - protoc plugin emitting TS.
- `prettier` (devDep) - formats the generated TS.

## Generation workflow

```bash
pnpm --filter @dcsv-io/d2-protos generate
```

`buf.gen.yaml` configures `ts-proto` with these options:
`esModuleInterop=true`, `outputServices=grpc-js`, `useExactTypes=false`,
`oneof=unions`, `useOptionals=messages`. Output is per-file under
`src/generated/d2/common/v2/{name}.ts`. The `generate` script then formats
`src/generated/` with `prettier` (a devDependency of this package).

## Parity with .NET

Every `.proto` file generates into both of these:

- .NET: `DcsvIo.D2.Result.Grpc` (via `Grpc.Tools` + csproj `<Protobuf Include>`)
- TS: `@dcsv-io/d2-protos/src/generated/...` (via Buf + ts-proto)

The `contracts/protos/` directory is the single source of truth. Neither
side hand-writes proto modules.

## Edge cases

- Codegen idempotency: re-running `pnpm generate` produces zero diff if
  no `.proto` changes. A change in the generated output shows up as a diff in the pull request.
- Generated code is committed to git, so a consumer does not run
  generation on first build.
- Generated code is excluded from coverage thresholds and from ESLint
  formatting (lives in `src/generated/`).
