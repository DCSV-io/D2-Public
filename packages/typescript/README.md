# packages/typescript/ - Shared TypeScript Libraries

> Parent: [`packages/`](../README.md)

Shared TypeScript libraries for Node and browser consumers. Most catalogs are emitted by code generation from the same
`contracts/` specs that drive the .NET shared libraries, so .NET and TypeScript cannot drift apart.

Each package has its own `README.md` with its public API, codegen workflow and dependencies. Generated files (`*.g.ts`)
are committed to git; each package refreshes them through its `prebuild` hook when the generator is available.

## Clusters

Some packages are grouped by concern area, and each group has an index README. The index lists and briefly describes the
packages of the group.

- [`auth/`](auth/README.md) - codegen-emitted scope / error-code / claim catalogs and the domain-safe auth-context interface
- [`geo/`](geo/README.md) - spec-driven geographic reference data and lookup contracts
- [`headers/`](headers/README.md) - per-transport wire-protocol header constant catalogs
- [`caching/`](caching/README.md) - twin of `DcsvIo.D2.Caching.*`: abstractions, local-default, distributed-redis and
  tiered, all **Built**; the shared backplane channel is `d2:cache:invalidations`

**Reading the chart**

- Each Foundation, Context, Auth-vocabulary, Headers and Wire-vocabulary package either only emits generated wire
  constants or is a set of pure runtime helpers, and none has internal sub-libraries.
- The `headers-*` packages have no runtime dependencies (they contain constants only); their catalogs are generated from
  `contracts/headers/` (sources committed).
- `auth-abstractions` has one runtime dep (`@dcsv-io/d2-result` - the `D2Result` shape returned by `AuthFailures.*` factories).
- `request-context-abstractions` re-exports types from `auth-context-abstractions` and contains the 1:1
  `PropagatedContextSerializer` class, generated from the same spec the .NET side uses.
- The `WIRE` subgraph holds the cross-language wire-vocabulary packages and the runtime packages that consume them.
  `@dcsv-io/d2-encryption-abstractions` (codegen `EncryptionDomains` closed enum and `EncryptionFrame` binary-layout
  constants) and `@dcsv-io/d2-messaging-abstractions` (codegen `DlqFailureMetadataFields` and `DlqFailureCauses`)
  contain constants only and have no runtime dependencies. `@dcsv-io/d2-encryption` is the runtime crypto core
  (WebCrypto AES-256-GCM v1 symmetric and P-256 ECDH-ES sealed v2, pinned byte for byte to the .NET encoder by
  known-answer tests) and depends only on `@dcsv-io/d2-encryption-abstractions`. `@dcsv-io/d2-messaging-rabbitmq` is the
  service-agnostic runtime for the consumer and the auto-encrypting publisher. It depends on `@dcsv-io/d2-encryption`
  for the body compose and decompose seams, on the wire catalogs, and on the foundation packages (`@dcsv-io/d2-result`,
  `@dcsv-io/d2-logging`, `@dcsv-io/d2-telemetry`, `@dcsv-io/d2-utilities`, `@dcsv-io/d2-request-context-abstractions`,
  `@dcsv-io/d2-headers-amqp`).

## Codegen workflow

Each codegen-driven package has a `prebuild` script that regenerates its catalogs when a generator is available. In a
public clone the generator may not be included. The `prebuild` script then skips regeneration, and `tsc` uses the
committed `*.g.ts` files. The generated files stay in git, so `pnpm install` and a build work without extra tooling.

The single source of truth for every spec-driven catalog is the matching `contracts/<topic>/` JSON spec, and the same
spec drives the .NET source generator. Constant catalogs that cross a language boundary are emitted from one spec and
are never mirrored by hand, so they cannot drift apart.

## Conventions

- Folder naming: lowercase, nested for grouped packages (`headers/http/`, `auth/abstractions/`).
- Package naming: `@dcsv-io/d2-<folder>` (for example `@dcsv-io/d2-headers-http`).
- Every package has a `README.md` with its public API, codegen workflow and dependencies.
- Every codegen-emitted package excludes `*.g.ts` from the coverage thresholds in `vitest.config.ts`; per-value pin
  tests in the package provide the coverage.
- Packages are published to npm under the `@dcsv-io` scope (see the release workflow).

## Convention divergences from .NET

The .NET and TypeScript sides aim for the same conceptual grouping. Where one side has only one package in a concept,
that package stays flat, because creating empty folders to force parity is an anti-pattern. These divergences are
accepted:

| .NET-side                                                                                                          | TS-side                                                  | Why divergence                                                                                          |
| ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `result/{core, envelope-source-gen}/`                                                                              | `result/` (flat, single pkg)                             | TS has no Roslyn source-gen siblings - generated catalogs ship as committed `*.g.ts`.                   |
| `context/{abstractions, source-gen}/`                                                                              | `request-context-abstractions/` (flat)                   | Same root cause - no TS-side source-gen pkg analogue.                                                   |
| `headers/{amqp, common, grpc, http, source-gen}/`                                                                  | `headers/{amqp, common, grpc, http}/`                    | TS-side has multi-transport pkgs (matching .NET) but no source-gen sibling.                             |
| `encryption/{core, domains-source-gen, frame-source-gen, in-process-keys-source-gen}/`                             | `encryption-abstractions/` + `encryption/`               | TS ships both the abstractions and the runtime crypto core; catalogs are committed `*.g.ts`.            |
| `messaging/{abstractions, rabbitmq, source-gen, dlq-failure-metadata-source-gen, otel-messaging-tags-source-gen}/` | `messaging-abstractions/` (flat) + `messaging/rabbitmq/` | TS ships the abstractions + a full RabbitMQ runtime (consumer AND the fused auto-encrypting publisher). |
| `protos` under contracts                                                                                           | `protos/` (flat)                                         | .NET-side proto compilation lives under `contracts/`; TS protos workspace is a flat pkg.                |
