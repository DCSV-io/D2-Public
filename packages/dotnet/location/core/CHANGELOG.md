## 0.1.13 - 2026-08-18
### Fixed

- The postal-code validator's regex pre-warm no longer fails the type initializer. The
  pre-warm ran one throwaway match inside the static constructor, and that match's
  50 ms timeout covers the compiled matcher's emit as well as the match. On a loaded
  machine that first match could exceed the timeout and throw out of the static constructor.
  .NET caches a failed type initializer for the life of the process, so every later
  postal-code validation would have thrown until the service restarted. The pre-warm
  now catches and ignores the timeout, and the next real call incurs the emit cost instead. The
  timeout still bounds real validation, which still fails closed on a timeout.
